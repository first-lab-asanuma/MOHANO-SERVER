매칭 조건과 후보 API
=====================

변경 목적
---------
사용자가 고른 국가, 성별, 연령대 조건을 저장하고 서버가 발급한 후보만 통화 신청 화면에
제공한다.

확정한 결정
------------
- 외부 API에는 유추 가능한 순번 대신 서버가 발급한 후보 ID를 사용한다.
- 후보 조회는 차단, 신고, 연령, 계정 상태를 먼저 제외한다.
- 후보 통화 신청은 `candidate_id`만 받으며, 클라이언트가 임의의 사용자 ID를 지정하지 못하게 한다.
- 연령 비표시 사용자의 실제 연령은 국가·성별과 함께 서버 내부 필터에만 사용한다. 공개 후보
  응답에서는 age를 null로 내려 카드에 표시하지 않는다.
- 후보는 최근 90초 이내에 foreground heartbeat를 보낸 온라인 사용자이거나, 통화 알림 수신에
  동의하고 유효한 push token을 등록한 사용자만 노출한다. 통화 신청 생성 시에도 동일 조건을
  다시 검사해, 그사이 응답 불가가 된 사용자에게는 신청을 만들지 않는다.

API와 데이터 요구사항
----------------------
- `GET /v1/me/match-preferences`, `PUT /v1/me/match-preferences`
- `GET /v1/matches/candidates`
- `POST /v1/call-requests`
- `GET /v1/call-requests/inbox?cursor={cursor}`
- `GET /v1/call-requests/{request_id}`
- `POST /v1/call-requests/{request_id}/accept|reject|cancel`
- match_preferences, call_requests 테이블

상세 요청·응답과 공통 규칙은 `07-api-contract.txt`를 기준으로 한다.

현재 구현 상태
--------------
- `app/services/matching_service.py`가 조건을 임시 저장하고, MySQL에 seed된 Sakura·Hana·Yuki·Mina
  테스트 후보를 국가·성별·연령 범위로 필터링한다. Sakura가 첫 후보로 표시된다.
- 실제 차단·신고·계정 상태·우선순위 계산과 MySQL `match_preferences`/`call_requests` 저장은
  아직 구현하지 않았다.

다음 작업 또는 미결정 사항
----------------------------
- 후보 우선순위(국가·성별·연령·언어·관심사), 하루 신청 제한, 후보 재노출 정책을 정한다.
- 통화 신청 만료 시간과 거절 사유 공개 여부를 정한다.
