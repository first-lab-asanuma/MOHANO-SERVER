MOHANO MVP API 계약
====================

상태
----
이 문서는 Flutter와 서버가 함께 참조하는 MVP API 목록과 공통 계약을 정한다. 익명·Google
인증과 프로필은 MySQL repository를 사용한다. 매칭 조건·통화·채팅은 현재 `MockStore`를
사용하는 더미 구현으로 열려 있어 FastAPI 재시작 시 상태가 사라진다. MySQL 전체 DDL은
Alembic `20261023_0002`까지 준비했으며, 사진 object storage를 제외한 나머지 repository 전환은 구현 대상이다.

목적
----
화면마다 임시 API를 추가하지 않고, 가입·프로필·매칭·통화·채팅 흐름에 필요한 최소 API를
먼저 확정한다. 음성 미디어는 API 범위가 아니며 WebRTC로 두 이용자가 직접 전송한다.

공통 계약
---------
- 기본 경로는 `/v1`이며 body는 JSON이다. 사진 원본은 private S3 호환 storage에 직접 PUT하며,
  FastAPI는 인증된 사용자에게만 짧게 만료되는 signed URL을 발급한다.
- health와 인증 교환을 제외한 API에는 `Authorization: Bearer <access JWT>`를 보낸다.
- 외부에 노출하는 사용자·후보·채팅·통화 ID는 UUID 등 유추 불가능한 값으로 한다.
- 날짜와 시간은 UTC ISO-8601 문자열, 목록은 `limit`과 cursor(`cursor` 또는 `before`/`after`)를
  사용한다.
- 성공 응답은 각 리소스 schema를 직접 반환한다. service가 판단하는 도메인 오류와 예상 밖의
  서버 오류는 `code`와 `message` JSON을 반환한다. 예상 밖의 오류는 항상
  `500/internal_server_error`로 응답하며 stack trace, credential, 개인정보를 body·로그에
  포함하지 않는다. 인증·요청 검증 오류의 body 통일은 실제 영속화 단계에서 함께 정리한다.
- 재전송되어도 중복 생성이 문제 되는 POST(메시지, 통화 신청, signaling)는 MySQL 전환 시
  `Idempotency-Key`를 저장해 중복을 막는다. 현재 더미 단계에서는 header만 허용하며 재전송
  결과를 보관하지 않는다.
- 언어는 `en`, `ja`, `ko`, 성별은 `man`, `woman`, `non_binary`처럼 표시 문구와 분리한 고정
  code를 저장한다. 국가·MBTI·관심사도 code를 저장하고 Flutter가 선택 언어에 맞게 표시한다.

MVP API 목록
------------

1. 시스템과 인증

| 상태 | 메서드 | 경로 | 역할 |
| --- | --- | --- | --- |
| 구현됨 | GET | `/v1/health` | 프로세스 health 확인 |
| 구현됨 | POST | `/v1/auth/anonymous` | 개발·초기 흐름용 익명 user와 JWT 발급 |
| 구현 예정 | POST | `/v1/auth/line/exchange` | LINE credential 검증 후 JWT 발급 |
| 구현됨 | POST | `/v1/auth/google/exchange` | 검증된 Google ID token 교환 후 JWT 발급 |
| 구현 예정 | POST | `/v1/auth/apple/exchange` | Apple credential 검증 후 JWT 발급 |
| 구현됨 | POST | `/v1/auth/refresh` | refresh JWT 회전과 access JWT 재발급 |
| 구현됨 | POST | `/v1/auth/logout` | 현재 refresh session 폐기 |
| 구현됨 | DELETE | `/v1/me/account` | 계정 탈퇴와 저장 개인정보 삭제 |
| 후순위 | GET | `/v1/ready` | MySQL 연결까지 확인하는 readiness |

Google 교환 API는 서버의 `MOHANO_GOOGLE_WEB_CLIENT_ID`와 ID token의 audience가 일치할 때만
JWT를 발급한다. LINE·Apple provider credential의 실제 검증에는 별도 client ID, key, redirect
정책이 필요하다. 값이 확정되기 전에는 해당 exchange API를 목업으로 열지 않는다.

`DELETE /v1/me/account`는 인증된 현재 사용자만 호출할 수 있다. 프로필·언어·관심사·사진 참조와
S3 호환 storage의 완료·임시 사진, 연결 identity, refresh session, 매칭 조건 및 저장된 통화·채팅
활동을 삭제한다. `users`에는 운영 감사용 비식별 ID, `deleted` 상태와 UTC 삭제 시각만 남긴다.
삭제된 사용자의 기존 access/refresh token은 즉시 거부되며, 제거한 identity는 새 가입에 다시 사용할 수 있다.

2. 내 프로필과 온보딩

| 상태 | 메서드 | 경로 | 역할 |
| --- | --- | --- | --- |
| 구현됨 | GET | `/v1/me/profile` | 앱 시작·프로필 화면의 내 정보 조회 |
| 구현됨 | PATCH | `/v1/me/profile` | 온보딩 및 프로필 편집 저장 |
| 구현됨 | POST | `/v1/me/profile/photos/upload-requests` | MIME·크기를 검증하고 10분 PUT URL 발급 |
| 구현됨 | POST | `/v1/me/profile/photos/upload-requests/{upload_id}/complete` | staging object 검증·승격 후 DB 참조 저장 |
| 구현됨 | DELETE | `/v1/me/profile/photos/{photo_id}` | storage object와 사진 참조 삭제 |

가용성·알림 계약
----------------

| 상태 | 메서드 | 경로 | 역할 |
| --- | --- | --- | --- |
| 구현됨 | GET | `/v1/me/availability` | 온라인 여부·통화 알림 동의·등록 token 유무 조회 |
| 구현됨 | POST | `/v1/me/availability/heartbeat` | foreground 앱의 최근 활동 시각 갱신 |
| 구현됨 | PUT | `/v1/me/availability` | 통화 알림 동의와 FCM/APNs device token 등록·폐기 |

온라인은 마지막 heartbeat가 90초 이내인 상태다. 후보·통화 신청 대상은 온라인이거나,
`call_notifications_enabled=true` 및 비어 있지 않은 push token을 모두 만족해야 한다. 토큰은
전송 전용 비공개 데이터이며 공개 프로필·후보 응답에 넣지 않는다.

`PATCH /v1/me/profile`는 nickname, nationality, gender, birth_date, age_visible, languages, mbti,
interest_codes, introduction을 받는다. 나이는 매년 자동으로 변해야 하므로 서버에는
`birth_date`만 비공개로 보관하고, 다른 사용자에게는 계산한 age만 반환한다. `age_visible`이
false이면 매칭에는 연령을 계속 사용하지만 공개 프로필의 age는 null로 반환한다. 온보딩 완료 여부는
서버가 필수값을 검증해 판단한다. 사진은 최대 5장, 대표 사진은 1장이라는 앱 정책을 서버에서도
검증한다. complete API는 10 MB 이하 JPEG, PNG, WebP, HEIC/HEIF magic bytes만 허용하고,
응답에는 DB object key 대신 15분 GET URL을 반환한다.

3. 매칭 조건과 후보

| 상태 | 메서드 | 경로 | 역할 |
| --- | --- | --- | --- |
| 구현됨 | GET | `/v1/me/match-preferences` | 현재 조건 조회 |
| 구현됨 | PUT | `/v1/me/match-preferences` | 국가·성별·연령대 조건 전체 저장 |
| 구현됨 | GET | `/v1/matches/candidates?limit=` | 내 조건으로 필터링한 최대 10명 후보 배치 조회. 미노출 후보 우선, 이후 가장 오래 전에 본 후보 우선 |
| 구현됨 | POST | `/v1/matches/candidates/{candidate_id}/pass` | 후보 패스 이력 저장. 후보를 영구 제외하지 않으므로 이후 배치에 재노출될 수 있음 |

후보 응답에는 후보 ID, 표시용 nickname, 연령(비공개 설정 시 null), 국가, 가능한 언어, MBTI, 관심사,
소개, 대표 사진 참조값만 넣는다. 후보 점수, 차단·신고 기록과 내부 user ID는 반환하지 않는다.

4. 통화 신청과 P2P 연결 제어

| 상태 | 메서드 | 경로 | 역할 |
| --- | --- | --- | --- |
| 더미 구현 | POST | `/v1/call-requests` | candidate_id로 통화 신청 생성 |
| 더미 구현 | GET | `/v1/call-requests/inbox?cursor=` | 수신자가 새로고침해 대기 신청을 조회 |
| 더미 구현 | GET | `/v1/call-requests/{request_id}` | 신청자·수신자의 현재 상태 조회 |
| 더미 구현 | POST | `/v1/call-requests/{request_id}/accept` | 수락하고 call session 생성 |
| 더미 구현 | POST | `/v1/call-requests/{request_id}/reject` | 수신 거절 |
| 더미 구현 | POST | `/v1/call-requests/{request_id}/cancel` | 신청자 취소 |
| 더미 구현 | GET | `/v1/call-sessions/{session_id}` | 통화 session 상태 확인 |
| 더미 구현 | POST | `/v1/call-sessions/{session_id}/signals` | offer/answer/ICE 신호 저장 |
| 더미 구현 | GET | `/v1/call-sessions/{session_id}/signals?after=` | 새 신호 polling 조회 |
| 더미 구현 | POST | `/v1/call-sessions/{session_id}/end` | 통화 종료 기록 |

통화 수락 응답은 `call_session_id`를 돌려준다. 수락 시 두 참여자 채팅을 생성 또는 재사용하고,
메시지 목록에는 `message_type: "call_connected"` 시스템 이벤트를 남긴다. 채팅 목록의 마지막
이벤트도 `last_message_type`으로 구분한다. signal payload는 짧게 만료하고, 두 참여자만 읽거나
쓸 수 있다. 서버는 음성을 전달하거나 보관하지 않는다.

5. 채팅

| 상태 | 메서드 | 경로 | 역할 |
| --- | --- | --- | --- |
| 더미 구현 | GET | `/v1/chats?cursor=` | 내 대화 목록과 마지막 메시지·unread 수 조회 |
| 더미 구현 | GET | `/v1/chats/{chat_id}/messages?before=` | 과거 메시지 cursor 조회 |
| 더미 구현 | POST | `/v1/chats/{chat_id}/messages` | 텍스트 메시지 저장 |
| 더미 구현 | POST | `/v1/chats/{chat_id}/read` | 마지막으로 읽은 메시지 갱신 |

대화방은 통화가 수락된 두 사용자에게만 열리는 것으로 시작한다. 화면 진입과 사용자의
새로고침에서만 조회하며 WebSocket, push, 자동 polling은 MVP에 넣지 않는다.

공개 전 필수 후순위
-------------------
- `POST /v1/users/{user_id}/block`, `DELETE /v1/users/{user_id}/block`: 차단
- `POST /v1/reports`: 신고
- 계정 삭제·데이터 보존 정책 API
- 요청 빈도 제한, 통화 신청 제한, 감사 로그 및 운영자 처리 흐름

구현 순서
---------
1. 소셜 인증 교환과 현재 사용자 의존성
2. 프로필·온보딩 저장 및 사진 signed upload/download
3. 매칭 조건·후보 API
4. 통화 신청 상태와 P2P signaling
5. REST 채팅과 읽음 상태
6. 공개 전 안전 기능(차단·신고·탈퇴)과 readiness

영향 파일과 다음 작업
----------------------
- 서버: `app/api/v1`, schema/service/repository, Alembic migration을 기능 순서대로 추가한다.
- Flutter: endpoint·요청/응답 model을 이 문서의 code와 상태값에 맞춘다.
- 다음으로 소셜 로그인에 사용할 LINE·Apple의 앱 식별자·redirect 정책, 사진 썸네일·EXIF 제거·
  staging object lifecycle 정책을 확정한다.
